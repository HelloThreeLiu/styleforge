# StyleForge AI 评分规范（RATING-RUBRIC）

> 评分代理（`styleforge-rater`）的唯一评分依据。本规范由策展人批准生效，策展人可随时修订权重、锚点与门禁，修订后自下一批评分起生效。
>
> 版本：v1.0 · 2026-08-21 · 与策展人共同确定（保真度优先权重 / 三方对照依据 / 轮内自动触发 / 页面内 rating.md 留痕）

---

## 0. 角色誓言

评分代理是**策展人的受托人**，不是生成者的队友。

1. **初次见面原则**：评分时视作第一次见到该页面。禁止以"生成时的心智"回忆或美化页面，一切结论重新阅读得出。
2. **证据强制**：每个维度的得分必须能指认证据——截图中的具体视觉特征、`index.html` 中的具体选择器/代码段、DESIGN.md 中的具体条目原文。给不出证据的印象分无效。
3. **拒绝通胀**：评分的目的是筛选值得沉淀的基因。分数通胀 = 劣质基因进入学习白名单。拿不准时，往低打。
4. **人类优先**：已有人类评分的页面永不改写。策展人在 Web 平台的任何改分永远覆盖 AI 评分。

---

## 1. 评分范围与产出

**对象**：`generated/pages/` 下所有 `rating == null` 的页面（含历史积压；`status` 通常为 `draft`）。

**每页产出（且仅此两项）**：

1. `meta.json`：写入 `rating`（1–5，0.5 步进），并将 `status: draft → published`（发布 ≠ 认可，评分本身承载判断；低分页永远不会触及 ≥4 沉淀线）。其余字段一字不动。
2. `rating.md`：完整评分留痕（模板见 §6）。

**禁止**：修改 `index.html` / `notes.md` / `tags_ai` / `lineage` / `tags_user`（人工标签留给策展人）等任何其他内容；删除或改写已存在的评分。

## 2. 五维评分表

| 维度 | 权重 | 考察点 |
|---|---|---|
| 风格保真度 | **30%** | 对照 lineage 指向的 DESIGN.md 原文：色彩角色、字体层级、组件样式（按钮/卡片/输入框）、圆角阴影体系、间距、Do's & Don'ts 遵守情况 |
| 视觉工艺 | **25%** | 层级清晰度、留白节奏、对齐一致性、对比度与可读性、细节打磨（hover/焦点态、微交互、装饰的一致性） |
| 完整性与内容 | **20%** | 导航/英雄区/≥3 内容区/页脚齐全；文案真实有质感（非占位 lorem）；375/768/1280 三档断点逐一成立 |
| 创意增值 | **15%** | 题材与风格的契合度、源风格之上的本地化发挥、是否有令人记住的亮点；novelty 不等于堆装饰 |
| 工程合规 | **10%** | 单文件自包含、字体系统回退栈、无外部图片、notes.md 三节质量及与实现的一致性 |

### 2.1 风格保真度锚点（30%）

- **5**：tokens 逐项可溯源（色值/字阶/圆角/阴影均能在 DESIGN.md 找到出处），Do's 全守、Don'ts 全避，神似原作气质。
- **4**：核心基因（主色角色 + 字阶 + 组件范式）忠实，个别次要 token 偏离但已在 notes 中声明且有理。
- **3**：框架像、细节漂——能认出师承，但色彩角色错位、字阶混乱或组件样式自创比例明显。
- **2**：仅借了名义（如只用了一个主色），结构与源风格基本无关；或 notes 声称的吸收点在页面中找不到。
- **1**：与源风格无实质关联。

### 2.2 视觉工艺锚点（25%）

- **5**：层级一眼可读，间距有节奏感，对齐严格，交互态完备，装饰服务于内容。
- **4**：整体干净利落，个别间距/对比度瑕疵。
- **3**：能看，但存在可指认的粗糙区（对齐散乱、留白失衡、对比度不足）。
- **2**：明显未经打磨，多处视觉冲突。
- **1**：视觉崩坏。

### 2.3 完整性与内容锚点（20%）

- **5**：结构齐全且每区都有真实、贴合题材的内容；三档断点下每个区域依然成立。
- **4**：结构齐全，内容真实，个别断点下有轻微挤压但可用。
- **3**：结构齐全但内容有明显凑数感，或某一档断点处理草率。
- **2**：缺关键结构（少于 3 个内容区/无页脚），或大面积占位文案。
- **1**：骨架占位页。

### 2.4 创意增值锚点（15%）

- **5**：在忠实基础上做出了令人记住的发挥，题材与风格互相成就。
- **4**：有清晰的本地化适配和 1–2 个亮点。
- **3**：合规完成，无亮点也无硬伤。
- **2**：机械套模板，题材与风格貌合神离。
- **1**：为创新而创新，破坏了源风格。

### 2.5 工程合规锚点（10%）

- **5**：全部技术底线满足，notes.md 三节翔实且与实现完全一致。
- **4**：底线满足，notes 略有水分或简略。
- **3**：底线满足，notes 流于形式。
- **2**：触碰一条技术底线（已触发门禁的情况）。
- **1**：多处违规。

## 3. 计分与门禁

### 计分

1. 每维独立打分（1–5，0.5 步进），乘权重求和得加权和；
2. **最终分 = ⌊加权和 × 2⌋ / 2（向下取半，宁低勿高）**。例：加权和 4.15 → 4.0；加权和 3.8 → 3.5。4.0 是沉淀线，不允许因四舍五入而"踩线晋级"。

### 门禁（触发即封顶，必须在 rating.md 中写明）

| 违规 | 判定方式 | 封顶 | 联动 |
|---|---|---|---|
| 外部图片资源 | `<img src="http…">`、CSS `url(http…)` 引用位图 | **2.5** | — |
| 任一档断点缺失 | 媒体查询未覆盖 375 / 768 / 1280 三档语义（看区间处理，非机械数 `@media` 次数） | **3.0** | 完整性 ≤2 |
| 字体无系统回退栈 | font-family 无 fallback | **3.0** | 合规 ≤2 |
| notes 声明与实现不符 | notes 声称的吸收点在页面中不存在 | **3.0** | 保真度 ≤2 |
| 页面骨架化 | 缺导航/英雄/≥3 内容区/页脚 | **2.5** | 完整性 ≤1 |

最终分 = min(加权取半分, 所有已触发封顶的最低值)。

## 4. 总分校准尺（先定档，再微调）

| 分 | 档位 | 含义 |
|---|---|---|
| 5.0 | 教科书 | 神还原且有显著增值，挑不出实质毛病，沉淀无争议 |
| 4.5 | 优秀 | 保真与工艺俱佳，仅存微瑕 |
| 4.0 | 良好（沉淀线） | 整体扎实、风格基因清晰可辨，个别短板不伤大局；**给 4.0 以上 = 愿意让它进学习白名单**，须有决心 |
| 3.5 | 中上 | 成立可看，但有可明确指出的偏离或粗糙区 |
| 3.0 | 及格 | 完整但平庸，或多处偏离源风格 |
| 2.5 | 不足 | 明显偏离、大面积粗糙，或触碰一条门禁 |
| ≤2.0 | 失败 | 合规崩坏或页面不成立（建议策展人考虑 archived） |

## 5. 反偏私协议

1. **三方对照强制**：`screenshot.png`（视觉呈现）+ `index.html`（真实实现）+ lineage 指向的 DESIGN.md（评分标尺），三者缺一不得为保真度打分。DESIGN.md 必须回读原文，禁止凭记忆。
2. **批内相对排序**：同批 ≥3 页时，先通览粗排出强弱序，再落分。落分后检查分布——一批全部 ≥4 或全部 <3 都要回头反思（通胀/通缩警报）。
3. **证据留痕**：rating.md 中每个维度至少 1 条可指认证据。
4. **向下取半**：见 §3，从机制上抑制踩线晋级。
5. **同源隔离**：评分代理与生成任务是两个角色。若发现自己在"替页面辩护"，立即停止并重读 §0。

## 7. 批量执行流程（操作规程）

1. **枚举**：扫描 `generated/pages/*/meta.json`，列出 `rating == null` 的页面。策展人显式点名重评时以点名清单为准（覆盖旧 rating.md 并更新 rating，需在汇报中注明覆盖了哪些旧分）。
2. **逐页评分**（建议并行分发子代理，每批 2–4 页）：
   读 `meta.json` → `notes.md` → lineage 指向的 DESIGN.md（`awesome-design-md/design-md/<name>/DESIGN.md` 或 `generated/styles/<id>/DESIGN.md`）→ `index.html` → 用读图能力查看 `screenshot.png` → 按 §2–§4 打分。
3. **落盘**：写 `rating.md`（§6 模板）；更新 `meta.json` 仅 `rating` 与 `status` 两字段，保持其余字段与缩进格式原样。
4. **校验**：`npm run validate` 通过（rating 合法性、JSON 完整性）。
5. **汇报**：输出汇总表（页面 / 总分 / 五维 / 一句话结论）、分数分布、最高最低分页，并提醒策展人可在 Web 平台复核改分。

---

## 8. 边界

- 评分代理**不执行沉淀**（沉淀仍走 AGENTS.md §10 / §11 的 promote 流程）。
- 评分代理**不写 `tags_user`**（人工标签权留给策展人）。
- 评分代理**不运行 `npm run sync`**（同步时机由轮协议或策展人决定）。
- 仅作用于 StyleForge 仓库（`F:\VibeCodingProject\UI-Design-Platform`），其他项目禁用。
